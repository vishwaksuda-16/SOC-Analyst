# Investigation 1: Unauthorized Account Creation & Persistence

## Executive Summary

**Case ID:** SOC-2024-001  
**Date:** June 15, 2024  
**Investigator:** Vishwak Sudarsanan  
**Severity:** CRITICAL  
**Status:** Confirmed - Data Exfiltration in Progress

An attacker compromised employee account `jsmith`, escalated privileges, created a backdoor administrative account, and exfiltrated sensitive company data across multiple external IP addresses. Investigation reveals coordinated multi-stage attack with persistence mechanism.

## Attack Chain Analysis

### Stage 1: Initial Access (02:47 AM)
```
Attacker obtains jsmith credentials (method unknown - likely phishing/password spray)
↓
RDP login from external IP 203.0.113.45
↓
Access to SALES-LAPTOP-04 with user privileges
```

**Key Indicators:**
- Login time: 2:47 AM (outside normal business hours)
- jsmith baseline: Works 9 AM - 5 PM EST only
- Source IP: External (203.0.113.45, not company network)
- LogonType 10: Remote Desktop Protocol (not local login)

**Confidence:** HIGH

---

### Stage 2: Privilege Escalation (02:48-02:49 AM)
```
PowerShell launched by explorer.exe
↓
net.exe executed by PowerShell
↓
Attacker gains system-level access
```

**Key Indicators:**
- ParentProcess anomaly: explorer.exe should not launch PowerShell
- net.exe is Windows account/network management tool
- Suspicious process chain: explorer → powershell → net.exe

**Confidence:** HIGH

---

### Stage 3: Persistence (02:52 AM)
```
New administrative account "backup_admin" created
↓
Account immediately tested with login
↓
Attacker ensures sustained access
```

**Key Indicators:**
- New account created by SYSTEM (account creation event)
- backup_admin name suggests intentional backdoor
- Immediate login test (02:55 AM) from same attacker IP
- Persistence mechanism in place even if jsmith password is reset

**Confidence:** CRITICAL

---

### Stage 4: Data Exfiltration (03:15 AM onwards)
```
Large files transferred to attacker-controlled servers
↓
Multiple external IPs used (load balancing/redundancy)
↓
Estimated 550 MB of company data stolen
```

**Key Indicators:**
- 250 MB + 180 MB + 120 MB = 550 MB total (abnormal volume)
- Multiple external IPs (coordinated infrastructure)
- HTTPS port 443 (encrypted, hides data contents)
- Timing: Immediately after backdoor account created

**Confidence:** CRITICAL

## Investigation Methodology

### Tools Used
- **SIEM:** Splunk Enterprise
- **Log Analysis:** Splunk Search Queries
- **Data Source:** Windows Event Logs, Firewall Logs, Network Telemetry
- **Process Mapping:** Manual timeline correlation

### Search Queries Executed

**Query 1: Find RDP logins**
```
EventID=4624 AND LogonType=10 AND IpAddress=203.0.113.45
```
Result: 2 events (jsmith and backup_admin logins)

**Query 2: Find process execution after login**
```
Computer=SALES-LAPTOP-04 AND User=jsmith AND EventID=4688 AND Timestamp>=02:47AM
```
Result: 4 events (explorer, powershell, net.exe, cmd.exe)

**Query 3: Find account creation**
```
EventID=4720 AND Timestamp>=02:47AM AND Timestamp<=03:00AM
```
Result: 1 event (backup_admin account created)

**Query 4: Find backup_admin activity**
```
User=backup_admin AND EventID=4624
```
Result: 1 event (successful login at 02:55 AM)

### Evidence Chain
1. Windows logs confirm event sequence
2. Firewall logs confirm data volume and external IPs
3. Process tree shows malicious parent-child relationships
4. Timing analysis shows coordinated, rapid attack
5. IOCs extracted and documented

## Lessons Learned

### What Worked
- ✅ SIEM correlation across multiple event types
- ✅ Timeline analysis revealed attack progression
- ✅ External IP correlation between different log sources
- ✅ Baseline deviation detection (2 AM login, new account)

### Gaps Identified
- ⚠️ RDP should have MFA (Multi-Factor Authentication)
- ⚠️ Privileged account creation not immediately alerted
- ⚠️ No EDR tool to detect payload download/execution
- ⚠️ Firewall rule allowed large outbound HTTPS (should be data loss prevention)

### Recommendations for Future Prevention
1. Implement multi-factor authentication (MFA) for all remote access
2. Enable privileged account management (PAM) for admin account creation
3. Deploy EDR (Endpoint Detection & Response) for behavioral analysis
4. Implement DLP (Data Loss Prevention) for outbound data transfer monitoring
5. Configure SIEM alerts for account creation outside normal hours
6. Establish baseline of normal outbound traffic per user/system
7. Implement alert on multiple failed logins followed by success
8. Enable real-time blocking of suspicious process chains
